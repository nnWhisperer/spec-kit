# Phase 1 Data Model: Subagent Orchestration as Installable Extension

**Feature**: 002-flow-extension-package
**Date**: 2026-05-13

This feature has no runtime database, no in-memory state, no API messages. The "data" is the set of files the extension ships and the structural relationships between them. This document captures those entities, their fields, and their lifecycle.

## Entity: Extension Manifest (`extension.yml`)

**Purpose**: The declarative root of the package. Consumed by `specify extension add` at install time and by `specify extension list` afterwards.

**Schema**: `schema_version: "1.0"`, validated by `specify_cli.extensions.ExtensionManifest`.

**Fields** (all required unless noted; the canonical skeleton lives in `contracts/extension-manifest.yml`):

| Field | Type | Value for this extension | Notes |
|---|---|---|---|
| `extension.id` | string (pattern `^[a-z0-9-]+$`) | `subagent-flow` | Per Clarifications Q1. |
| `extension.name` | string | `Subagent Flow Orchestrator` | Human-readable; shown in `specify extension list`. |
| `extension.version` | string (semver `X.Y.Z`) | `1.0.0` for initial release | Bumped each time agent bodies or scripts change. |
| `extension.description` | string (<200 chars) | `Per-feature orchestrator that runs specify → clarify → plan → tasks → analyze → implement as isolated subagents with a chunked implement loop.` | Catalogue-visible. |
| `extension.author` | string | `subagent-flow maintainers` (placeholder; replace with real org/handle) | |
| `extension.repository` | URL | Fork repository URL | |
| `extension.license` | string | `MIT` | Matches the fork's existing licensing. |
| `extension.homepage` | URL (optional) | Fork README URL | |
| `requires.speckit_version` | string (version specifier) | `>=0.2.0` | Decision 1, Decision 4, FR-014. |
| `requires.tools` | array | `[]` | FR-014: empty per the I1 realignment. Host-agent capability is narrative in README. |
| `provides.commands` | array | One entry: `{name: speckit.subagent-flow.run, file: commands/speckit.subagent-flow.run.md, description: ...}` | FR-003. |
| `provides.config` | array | (omitted) | No config file shipped. |
| `hooks` | object | (omitted) | No workflow-phase hooks. The orchestrator runs only when the user invokes its slash command directly. |
| `tags` | array (2–10 strings) | `["orchestrator", "subagent", "workflow", "claude-code"]` | Catalogue discovery. |
| `defaults` | object | (omitted) | No tunable defaults. |

**No `provides.agents` block.** Per research.md Decision 6 (rewritten after the analyze pass), the I2 question — "should the manifest declare the seven baked agent files for the installer to copy?" — is pre-decided as NO. The manifest uses only schema-1.0 fields that the existing `ExtensionManifest` validator and `ExtensionManager` installer already interpret. Subagent-file provisioning is handled by the orchestrator's Phase 0 preflight (FR-013) + the bundled `build-claude-agents.sh` regen script. The seven baked agent files ship at `extensions/subagent-flow/agents/` inside the extension; the installer's standard `shutil.copytree` places them at `.specify/extensions/subagent-flow/agents/`; the regen script copies them from there to `.claude/agents/` on the user's first orchestrator invocation (the preflight prints the exact command). This is the option (b) commitment; option (a) (schema-extended `provides.agents`) is rejected and preserved in research.md Decision 6 for trail.

**Validation rules** (enforced by `ExtensionManifest` as it exists today in `src/specify_cli/extensions.py`):
- `extension.id` matches `^[a-z0-9-]+$`.
- `extension.version` parses as a valid PEP-440 version (`packaging.version.Version`); for this extension, `1.0.0` matches.
- `requires.speckit_version` is a valid PEP-440 specifier set (`packaging.specifiers.SpecifierSet`).
- `provides` must contain at least one of `commands` or `hooks` (this extension provides `commands` only).
- Each `provides.commands[].name` must match `^speckit\.subagent-flow\.[a-z0-9-]+$` (the `<ext-id>` segment must equal `extension.id`).
- Each `provides.commands[].file` must resolve to a file that exists inside the extension directory (path-traversal-safe; enforced by the installer).
- Unknown top-level keys and unknown keys under `provides`/`requires` are silently accepted by the current validator but are not used by this extension.

## Entity: Orchestrator Command File (`commands/speckit.subagent-flow.run.md`)

**Purpose**: The Markdown body of the orchestrator slash command. Executed by the AI agent when the user invokes `/speckit.subagent-flow.run`.

**Structure**:

```
---
description: <human-readable description, copied to manifest>
---

# Speckit Subagent Flow

<orchestrator body — copied verbatim from the fork's .claude/commands/speckit-flow.md
 with the following three textual edits:>

  1. Description paragraph updated to reflect the namespaced command name.
  2. Every reference to `scripts/bash/count-open-tasks.sh` rewritten to
     `.specify/extensions/subagent-flow/scripts/bash/count-open-tasks.sh`.
     (Decision 7: paths authored in installed form; no installer rewriting.)
  3. A new inline bash bootstrap block inserted at the very top of the body,
     before Phase 1 specify. The block implements FR-013 (Path 3) exactly:
       - Set SRC=.specify/extensions/subagent-flow/agents and DST=.claude/agents.
       - If $SRC does not exist as a directory, emit a multiline error and
         exit 1. The error MUST contain three literal elements:
           (a) the literal list of missing source paths (one per line),
           (b) the recovery command verbatim:
               `specify extension add subagent-flow`
           (c) the README path verbatim:
               `.specify/extensions/subagent-flow/README.md`
       - `mkdir -p "$DST"`.
       - For p in specify plan tasks analyze implement checklist taskstoissues:
           s=$SRC/speckit-$p.md; d=$DST/speckit-$p.md
           if [ ! -f "$s" ]: emit per-file source-missing error, exit 1.
           else: `cmp -s "$s" "$d" || cp "$s" "$d"`
       - After the loop completes without exit, proceed to Phase 1.
     The block does NOT prompt the user. Under the happy path (source dir
     present, all seven sources present) the user sees no extra output;
     under stale-deploy or fresh-install the bootstrap silently copies
     and proceeds.
```

**FR-013 error contract** (pinned by spec U1 realignment, Path 3 form):

The bootstrap error MUST contain three literal elements, and is surfaced only when the source dir or one of the seven source files under `.specify/extensions/subagent-flow/agents/` is missing — i.e., the install is corrupted. The orchestrator is the sole emitter of this message. Under the recoverable cases (deployed copy missing or stale-but-source-OK), the bootstrap self-heals silently and proceeds without surfacing the error.

**Validation rules**:
- File MUST start with a YAML frontmatter block containing a `description` field.
- File MUST exist at the path declared in `provides.commands[0].file`.
- File MUST contain the literal string `.specify/extensions/subagent-flow/scripts/bash/count-open-tasks.sh` (the helper path, FR-005).
- File MUST contain the literal string `.specify/extensions/subagent-flow/agents` (the bootstrap source dir, FR-013).
- File MUST contain the literal string `specify extension add subagent-flow` (the recovery command surfaced when the source dir is missing, FR-013).
- File MUST contain the literal string `.specify/extensions/subagent-flow/README.md` (the README path, FR-013).
- File MUST contain a `cmp -s` invocation (the content-aware copy primitive, Decision 9).
- The body MUST NOT directly write to `spec.md`, `plan.md`, or `tasks.md` (constitution Principle IV — currently satisfied by the fork's body and preserved by this rewrite; the bootstrap writes to `.claude/agents/` only).

**Relationships**:
- References `.specify/extensions/subagent-flow/scripts/bash/count-open-tasks.sh` (the installed path; written directly in body per Decision 7).
- References `.specify/extensions/subagent-flow/agents/speckit-<phase>.md` as the SOURCE side of the bootstrap copy.
- References `.claude/agents/speckit-<phase>.md` as the DESTINATION side of the bootstrap copy, AND as the `Agent` tool's `subagent_type=speckit-<phase>` resolution target after the bootstrap completes.
- References `.specify/extensions/subagent-flow/README.md` (surfaced to the user only on the source-dir-missing error path).
- References `speckit-clarify` via the `Skill` tool (inline expansion).

## Entity: Generator Script (`scripts/bash/build-claude-agents.sh`)

**Purpose**: Reads a phase source layout (flat `templates/commands/<phase>.md` or skill `.claude/skills/speckit-<phase>/SKILL.md`) and writes one `speckit-<phase>.md` per workflow phase to an output directory.

**Inputs** (environment variables, both optional):
- `SRC_DIR`: source directory; auto-detected if unset (prefers `templates/commands`, falls back to `.claude/skills`).
- `OUT_DIR`: output directory; defaults to `.claude/agents`.

**Internal state** (already exists in fork's script):
- `SKIP_PHASES = (clarify constitution)` — phases excluded per Constitution Principle III.
- `PHASE_TOOLS` — per-phase tool surface map (plan gets WebFetch/WebSearch; implement gets TodoWrite; analyze and taskstoissues get read-only; rest get default).
- `DEFAULT_TOOLS = "Read, Write, Edit, Bash, Glob, Grep"` — fallback surface.

**Outputs**: One `speckit-<phase>.md` per non-skipped workflow phase. Each output file has:
- Frontmatter `{name, description, tools}` rewritten from the source.
- A body identical to the source's body (post-frontmatter).
- An `AUTO-GENERATED` warning header inserted between frontmatter and body.

**Validation rules**:
- Must exit non-zero with a descriptive error if `$SRC_DIR` does not exist.
- Must silently skip extension command skills (skill names with a hyphen after stripping `speckit-`, e.g., `speckit-git-commit`) when running against the skill layout.
- Must be idempotent: re-running against the same source MUST produce byte-identical outputs (FR-011).

**Used by**:
- Maintainer CI workflow (`.github/workflows/subagent-flow-resync.yml`) — automated bake against upstream.
- Power users who customise their local SKILLs (manual invocation via `bash`).

**Not used by**: ordinary end users (Clarifications Q2).

## Entity: Open-Task Helper (`scripts/bash/count-open-tasks.sh`)

**Purpose**: Given a path to a `tasks.md`, prints the integer count of unchecked task lines (`^- \[ \]`). Used by the orchestrator's Phase 6 loop for disk-as-truth termination.

**Inputs**: `$1` — path to `tasks.md`.

**Outputs**: stdout — single integer count (`0` if the file is missing or has no unchecked tasks).

**Validation rules**:
- `$1` missing or empty: usage on stderr, exit 1.
- File at `$1` does not exist: print `0`, exit 0.
- File exists, no `- [ ]` lines: print `0`, exit 0.

**Used by**: the orchestrator command file's Phase 6 loop.

**Lifecycle**: shipped at extension version's frozen content; bumped along with the manifest if its behaviour ever changes (it has not changed since feature 001 introduced it).

## Entity: Pre-Baked Subagent File (`agents/speckit-<phase>.md`)

**Purpose**: One file per non-skipped workflow phase. Loaded by the AI agent when the orchestrator invokes `Agent(subagent_type=speckit-<phase>)`. The file's body expands as the subagent's instructions.

**Fields** (frontmatter):
- `name`: `speckit-<phase>`.
- `description`: copied from the source `templates/commands/<phase>.md`'s description.
- `tools`: per-phase, per the generator's `PHASE_TOOLS` map.

**Body**: copied verbatim from the source, with the `AUTO-GENERATED from <source-path> by scripts/bash/build-claude-agents.sh. Do not edit by hand.` warning header.

**The seven files**: `speckit-specify`, `speckit-plan`, `speckit-tasks`, `speckit-analyze`, `speckit-implement`, `speckit-checklist`, `speckit-taskstoissues`. (Constitution v1.1.1's SKIP list excludes `clarify` and `constitution`, so neither is present in the baked set.)

**Two-state lifecycle** (Path 3 per research.md Decision 6 + Decision 9):

The Pre-Baked Subagent File entity lives in two distinct on-disk states with different ownership:

- **Source copy** at `.specify/extensions/subagent-flow/agents/speckit-<phase>.md`: owned by the extension, shipped as part of its tracked payload, deterministically refreshed by `specify extension add` and removed by `specify extension remove`.
- **Deployed copy** at `.claude/agents/speckit-<phase>.md`: created and refreshed by the orchestrator's inline bootstrap; NOT owned by the extension after bootstrap; persists across `specify extension remove`.

The state transition from source → deployed is performed by the orchestrator's inline bash bootstrap (Decision 9), gated by `cmp -s` content comparison. There is no other transition into the deployed state.

**State transitions** (Path 3):

1. Maintainer CI runs the generator against upstream `templates/commands/*.md` → writes seven files into `extensions/subagent-flow/agents/` (source-copy authoring).
2. Maintainer reviews the diff (via PR) and merges; the extension's version is bumped if any agent body changed.
3. End user installs the extension → spec-kit's `ExtensionManager.install_from_directory()` runs `shutil.copytree` and the seven source files land at `.specify/extensions/subagent-flow/agents/`. The installer does NOT copy them into `.claude/agents/` — no `provides.agents` schema field, no install hooks. `.claude/agents/` may be empty of speckit-* files at this point.
4. End user invokes `/speckit.subagent-flow.run` for the first time → orchestrator's inline bootstrap runs at the top of the body. For each phase, `cmp -s` reports the deployed copy as missing (the file doesn't exist) → `cp` copies source to deployed. After the loop, `.claude/agents/speckit-*.md` is populated and content-matches the source dir. Orchestrator proceeds to Phase 1.
5. End user upgrades the extension → spec-kit overwrites `.specify/extensions/subagent-flow/agents/` with the new source payload. On the next `/speckit.subagent-flow.run` invocation, the bootstrap's `cmp -s` detects content drift between source and deployed → `cp` refreshes the deployed copies transparently. No user action required.
6. End user manually deletes one or more deployed copies → on the next invocation, the bootstrap detects the missing files and re-copies them from source. Self-healing.
7. End user manually edits a deployed copy → on the next invocation, the bootstrap's `cmp -s` detects content drift and overwrites the edit with the source content. Hand-edits are not preserved (the files carry the `AUTO-GENERATED` header for this reason; spec edge case documents this).
8. End user removes the extension → spec-kit's `ExtensionManager.remove()` deletes `.specify/extensions/subagent-flow/`. The seven `.claude/agents/speckit-*.md` files are LEFT IN PLACE — they belong to the user's project now, not to the extension's tracked payload. The README documents this as deliberate and provides `rm .claude/agents/speckit-{specify,plan,tasks,analyze,implement,checklist,taskstoissues}.md` as the one-line manual cleanup. `--keep-config` is a no-op.
9. End user re-installs the same version → the source dir is overwritten idempotently (FR-011); on the next orchestrator invocation, the bootstrap's `cmp -s` matches and no copy happens.
10. **Install corruption** (source dir missing or partial — e.g., extension dir was deleted by hand without `specify extension remove`): on the next orchestrator invocation, the bootstrap detects the missing source dir/files and emits the FR-013 error pointing at `specify extension add subagent-flow` for recovery, then exits 1 without invoking any subagent. This is the only user-visible error path.

**Validation rules** (enforced at maintainer CI time, not at install time):
- Each file has a `name: speckit-<phase>` frontmatter that matches its filename.
- Each file contains the `AUTO-GENERATED` warning header.
- No file's body is empty.
- Re-running the generator MUST produce byte-identical outputs against the same source (FR-011, SC-005).

## Entity: Maintainer CI Workflow (`.github/workflows/subagent-flow-resync.yml`)

**Purpose**: Periodically re-bake the seven agent files against upstream `templates/commands/*.md` and surface drift to the maintainer via PR.

**Triggers**:
- `workflow_dispatch` (manual; also the only trigger `act` exercises).
- `schedule` (cron, ignored by `act`; suggested `0 6 * * 1` — Monday 06:00 UTC).

**Steps** (high-level; full YAML lives in source tree at implementation time):
1. `actions/checkout@<pinned>` — fetch the fork's main branch.
2. `bash extensions/subagent-flow/scripts/bash/build-claude-agents.sh` with `SRC_DIR=templates/commands` and `OUT_DIR=extensions/subagent-flow/agents`.
3. `git diff --quiet extensions/subagent-flow/agents/` — if clean, exit 0.
4. Otherwise, `peter-evans/create-pull-request@<pinned>` opens a PR titled `chore(subagent-flow): resync agents against upstream`.

**Local-verification command** (documented in README maintainer section):

```bash
act workflow_dispatch -W .github/workflows/subagent-flow-resync.yml --container-architecture linux/amd64
```

## Entity: README (`extensions/subagent-flow/README.md`)

**Purpose**: Single user-facing documentation file. FR-007 (SC-007) requires this be sufficient for first-read install/use/uninstall.

**Required sections**:
1. **What this extension does** — one paragraph.
2. **Install** — exact `specify extension add subagent-flow` command.
3. **First-run experience** — explanation that on first `/speckit.subagent-flow.run` invocation the orchestrator's inline bootstrap silently copies the seven baked agent files from `.specify/extensions/subagent-flow/agents/` into `.claude/agents/`. The user takes no action. Subsequent invocations are no-ops unless an extension upgrade has changed source content, in which case the bootstrap transparently refreshes `.claude/agents/` (Path 3 per research.md Decision 6 + Decision 9).
4. **Use** — how to invoke `/speckit.subagent-flow.run` and what to expect (phase-by-phase summary).
5. **Uninstall** — `specify extension remove subagent-flow` (removes `.specify/extensions/subagent-flow/` only). Document that the seven `.claude/agents/speckit-<phase>.md` files are deliberately left in place: they belong to the user's project after bootstrap, contain upstream-derived content useful for direct `/speckit.<phase>` invocations, and can be manually removed with `rm .claude/agents/speckit-{specify,plan,tasks,analyze,implement,checklist,taskstoissues}.md` if undesired. Note that the spec-kit `--keep-config` flag is a no-op for this extension.
6. **Power user: customising agent bodies** — when and how to re-run `bash .specify/extensions/subagent-flow/scripts/bash/build-claude-agents.sh` (after customising local SKILLs and re-deriving the source agent files; this writes into the source dir at `.specify/extensions/subagent-flow/agents/`, then the next orchestrator invocation propagates the change to `.claude/agents/` automatically via the bootstrap's `cmp -s` content check).
7. **Compatibility** — host agent capability requirements (the `Agent` tool for subagent delegation and the `Skill` tool for inline clarify) are documented narratively per FR-014; spec-kit `>=0.2.0`. Install does not gate on host capability.
8. **Recovery** — short note explaining the one user-visible error path: if the source dir `.specify/extensions/subagent-flow/agents/` is missing or partially populated (a sign of an interrupted install or hand-deletion of the extension dir), the orchestrator's bootstrap exits with an error pointing at `specify extension add subagent-flow` for recovery.
9. **Maintainer section** (after a `---` divider): how to run the CI sync workflow locally with `nektos/act`.

**Validation rules**: No automated; manual review against SC-007 ("sufficient on first read").
